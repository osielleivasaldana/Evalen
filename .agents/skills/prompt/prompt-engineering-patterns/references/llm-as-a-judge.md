# LLM-as-a-Judge Reference Guide

Using large language models (LLMs) to evaluate the quality of outputs generated by other LLMs. This pattern provides a highly scalable, flexible, and automated alternative to human evaluation.

---

## 1. Core Evaluation Patterns

### Pattern A: Absolute Grading (G-Eval Style)
An LLM evaluates a single output against a detailed rubric and assigns a score (typically 1-5 or 1-100) along with a detailed reasoning.

* **Best for:** Consistent quality control, regression testing, and computing aggregate metrics (e.g., Average Quality Score).
* **Key requirement:** Highly explicit, granular rubrics for each grade level to minimize variance.

### Pattern B: Pairwise Comparison (Arena Style)
An LLM receives an input and two candidate outputs (Response A and Response B) and decides which response is better, or if they are tied.

* **Best for:** A/B testing prompt modifications, comparing different models, or ranking generations.
* **Key requirement:** Swapping the order of responses (A/B vs B/A) to control for position bias.

### Pattern C: Constraint Validation & Linting
An LLM checks if specific rules, safety guardrails, or structural constraints were violated in the output.

* **Best for:** Filtering out halluncinations, checking for PII leaks, validating formatting instructions, and ensuring prompt injections didn't bypass system instructions.

---

## 2. Designing the Judge Prompt

An effective LLM-as-a-Judge prompt must establish a clear persona, define strict rubrics, and mandate a Chain-of-Thought reasoning path.

### Key Prompt Components:
1. **Role Definition:** Establish the judge as an expert auditor or domain specialist (e.g., "You are an expert recruitment quality inspector...").
2. **Contextual Grounding:** Provide the original raw input, the candidate output, and (optionally) a reference ground truth.
3. **Granular Rubric:** Do not just ask "Is this good?". Provide a precise definition of each score:
   * *Score 5:* Fully complete, accurate, contains zero hallucinations or formatting errors, and matches all raw data.
   * *Score 3:* Mostly accurate and complete, but misses minor details or contains small formatting glitches.
   * *Score 1:* Severely incorrect, contains hallucinations, or completely fails the task guidelines.
4. **Reasoning-First (CoT):** Force the LLM to write out the detailed critique *before* outputting the final score. This forces the LLM to "think" and yields significantly more accurate scores.
5. **Structured JSON Output:** Enforce a strict JSON output to make evaluation parsing automated.

---

## 3. Sample Judge Prompt Template

Below is a template for absolute grading of CV parsing / extraction quality:

```
You are an expert AI Quality Assurance Auditor. Your task is to evaluate the quality of a structured CV extraction against the original raw CV text.

Evaluate the extraction on the following criteria:
- **Completeness**: Were all jobs, titles, dates, and education details from the raw text captured?
- **Factual Accuracy**: Are there any hallucinations, misattributions, or incorrect details?
- **Format Adherence**: Does the extraction follow formatting rules (e.g. no RUT in name, correct date structures)?

Use the following rubric to determine the score:
- **5 (Perfect)**: 100% complete, highly accurate, formatting instructions followed perfectly.
- **4 (Good)**: Minor omissions (e.g., a short certification or secondary skill missed), but 100% accurate and well-formatted.
- **3 (Acceptable)**: A few details are missing or there are minor formatting issues, but no major factual errors.
- **2 (Poor)**: Significant information is missing (e.g. an entire job profile missed) or contains minor hallucinations.
- **1 (Failed)**: Major hallucinations, incorrect dates/companies, or the output is completely empty/unusable.

[ORIGINAL RAW CV]
{raw_cv_text}

[STRUCTURED EXTRACTION LOGIC]
{extracted_json}

Provide your response in JSON format matching this schema:
{
  "reasoning": "Step-by-step analysis explaining the completeness, accuracy, and formatting check...",
  "completeness_score": 1 to 5,
  "accuracy_score": 1 to 5,
  "formatting_score": 1 to 5,
  "overall_score": 1 to 5,
  "missed_details": ["Detail 1", "Detail 2"],
  "hallucinations_detected": ["Hallucination 1"]
}
```

## 4. Mitigating Judge Biases

LLMs are prone to several cognitive biases when acting as judges. Apply these mitigation strategies:

| Bias Type | Description | Mitigation Strategy |
| :--- | :--- | :--- |
| **Position Bias** | In pairwise comparisons, the judge prefers Response A over Response B simply because it was presented first. | Run the evaluation twice, swapping the order of the candidates (A/B and B/A). Only accept a win if it wins in both positions, otherwise declare a tie. |
| **Length Bias** | The judge prefers longer, more verbose responses even if they contain less relevant information. | Add explicit criteria to penalize fluff or enforce a character/word limit in the rubric. |
| **Self-Enhancement Bias** | An LLM prefers outputs generated by itself rather than outputs generated by other models. | Keep evaluation models consistent or use a stronger model (e.g., GPT-4o, Claude 3.5 Sonnet) to evaluate weaker models. |
| **Tone Bias** | The judge is swayed by polite, authoritative, or formal language over factual accuracy. | Instruction: "Ignore tone and formatting style; evaluate purely on completeness and semantic equivalence to the source text." |
